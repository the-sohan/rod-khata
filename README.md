# রডখাতা — লোকাল সংস্করণ ০.৬

এই প্রজেক্টটি শেখা ও পরীক্ষার জন্য। দোকানের PC হবে Windows; মালিকের ফোন Android। Mac-এ তৈরি ও পরীক্ষা করা হয়েছে। একই বিলে একাধিক পণ্য, কেজি/পিস, ক্রেতার তালিকা ও বাংলা রসিদ প্রিন্ট আছে। PC থেকে Drive backup যাচাই করা হয়েছে; APK-তে remote dashboard-এর কোড আছে। নতুন installation-এ নিজের Cloud OAuth setup লাগবে; বাস্তব Android ফোনে পরীক্ষা বাকি। আসল দোকানের হিসাব চালু করার আগে মালিক/কর্মচারীর login, বিল সংশোধন/ফেরত এবং recovery ব্যবস্থাও সম্পূর্ণ করতে হবে।

## ১. কী ইনস্টল লাগবে

- **Node.js LTS 24 বা নতুন:** Next.js ও লোকাল SQLite চালাবে। https://nodejs.org/en/download
- **VS Code:** প্রজেক্টের ফাইল দেখবেন ও পরিবর্তন করবেন। https://code.visualstudio.com
- **Git:** কোডের ইতিহাস রাখবেন। https://git-scm.com/downloads
- **Chrome:** PC-তে অ্যাপ ও Android-এ ভবিষ্যৎ dashboard পরীক্ষা করবেন।

প্রথমবার repository clone করে dependency ইনস্টল করুন:

```bash
cd ~/Desktop
git clone https://github.com/the-sohan/rod-khata.git
cd rod-khata
npm ci
```

Private repository হওয়ায় GitHub access লাগবে। এই লোকাল ব্যবস্থায় Docker, Supabase Cloud বা VPS প্রয়োজন নেই। Google Drive সেটআপের নির্দেশনা `android/GOOGLE-DRIVE-SETUP.txt`-এ। Android-এর source `android/` এবং dashboard `apps/owner/`-এ; APK build-এর নির্দেশনা `android/README.md`-এ।

## ২. কোথায় কী আছে

```text
rod-shop/
  apps/pc/       PC থেকে এন্ট্রি ও হিসাব দেখার Next.js অ্যাপ
  apps/owner/    শুধু দেখার mobile dashboard; ভবিষ্যৎ static hosting উপযোগী
  lib/          SQLite ও হিসাবের নিয়ম
  scripts/      চালু করা, snapshot ও backup-এর background কাজ
  tests/        হিসাব ও backup ফেরত আনার পরীক্ষা
  data/         চলার সময় তৈরি হবে; নিজের দোকানের ব্যক্তিগত তথ্য
```

`data/shop.sqlite` মূল ডেটাবেস। `data/owner-snapshot.json` মোবাইলের জন্য সর্বশেষ তৈরি হিসাব। `data/backups/` যাচাই করা database backup। এসব Git-এ যাবে না। Google Drive upload আছে; backup encryption ও retention cleanup এখনও বাকি। OAuth tokens `data/google-drive`-এ encrypted local file-এ থাকে এবং database backup-এ যায় না।

## ৩. Mac-এ এখন চালাবেন

Terminal-এ লিখুন:

```bash
cd ~/Desktop/rod-khata
npm run dev
```

দুটি ঠিকানা খুলুন:

- PC অ্যাপ: http://127.0.0.1:3000
- মালিকের mobile dashboard-এর লোকাল preview: http://127.0.0.1:3001

অথবা `Start-Rod-Shop-Mac.command` খুলুন। Node-এর অনুমতি/Path সমস্যা হলে উপরের Terminal পদ্ধতি ব্যবহার করুন। একই সঙ্গে অ্যাপের দ্বিতীয় কপি চালাবেন না। বন্ধ করতে Terminal-এ **Control + C** চাপুন।

## ৪. Windows-এ প্রথমবার

1. Node.js LTS, VS Code ও Git ইনস্টল করুন। Installer-এর default setting রাখুন।
2. নতুন Terminal খুলে `node -v`, `npm -v`, `git --version` দিয়ে যাচাই করুন। Node 24 বা নতুন লাগবে।
3. repository Windows-এর Desktop-এ clone করুন, অথবা source-এর ফোল্ডারটি নিন। Mac-এর `node_modules`, `.next`, `out` বা পরীক্ষার `work` ফোল্ডার কপি করার প্রয়োজন নেই। নতুন দোকানে Mac-এর `data` কপি করবেন না।
4. `Start-Rod-Shop-Windows.cmd`-এ double-click করুন। প্রথমবার npm package ডাউনলোড হবে; তখন ইন্টারনেট লাগবে।
5. Terminal চালু রাখুন এবং Chrome-এ উপরের দুটি ঠিকানা খুলুন।

ভবিষ্যতে installer/service তৈরি হলে PC চালুর সঙ্গে এটি নিজে চলবে। Windows startup service এখনও বাকি। Android মালিকের APK তৈরি হয়েছে; ইনস্টল ও build নির্দেশনা `android/README.md`-এ আছে।

## ৫. হাতে প্রথম পরীক্ষা

এগুলো কেবল পরীক্ষার সংখ্যা; আসল ক্রেতার তথ্য এখন ব্যবহার করবেন না।

1. **পণ্য ও স্টক → পণ্য যোগ করুন:** নাম `পরীক্ষার রড ১৬ মিমি`, শুরুর স্টক `5000` কেজি, দর `80` টাকা। শুরুর স্টক কোনো আগের দেনা তৈরি করে না।
2. **ক্রেতার তালিকা → নতুন ক্রেতা:** নাম `পরীক্ষার ক্রেতা`, ঠিকানা ও মোবাইল সেভ করুন। তারপর **নতুন এন্ট্রি → বিক্রি** থেকে ক্রেতা ও পণ্য বেছে পরিমাণ `1000`, দর `80`, জমা `50000` দিন।
3. সারাংশে বিক্রি `80,000`, পাওনা `30,000`, স্টক `4,000` কেজি হবে।
4. **বাকি আদায়:** একই ক্রেতার `10000` টাকা আদায় লিখুন। পাওনা হবে `20,000`।
5. **ব্যাকআপ ও আপডেট → প্রিভিউ এখন আপডেট করুন** চাপুন।
6. মালিকের preview খুলুন; দরকার হলে refresh বাটন চাপুন। একই হিসাব দেখাবে; সেখানে কোনো entry form নেই।

### নতুন সুবিধাগুলো ব্যবহার

- **Android APK:** PC-র `ব্যাকআপ ও আপডেট → Android APK ডাউনলোড` থেকে নিন। অ্যাপ খুলে `তিন মাসের ডেমো দেখুন → রিপোর্ট → ফিল্টার` দিয়ে প্রথম পরীক্ষা করুন। APK-তে আসল দোকানের তথ্য নেই। ফোনে ইনস্টল করার বাস্তব পরীক্ষা এখনও বাকি।
- **মোবাইল রিপোর্ট:** দৈনিক/সাপ্তাহিক/মাসিক/বার্ষিক/নিজের তারিখের রিপোর্ট। ফিল্টার নিচ থেকে খুলবে; মাস ও বছর আলাদা picker, আর পণ্য/ক্রেতা/দিনের হিসাব কার্ডে দেখাবে। সার্চ, সাজানো ও প্রতিটি কার্ডের বিস্তারিত আছে। সব হিসাব সর্বশেষ PC snapshot-এর সময় পর্যন্ত।
- **নিজের দোকানের মোবাইল সংযোগ:** একই বিশ্বস্ত Wi-Fi-তে PC ও ফোন রাখুন। PC-তে `ব্যাকআপ ও আপডেট → মোবাইলের Wi-Fi সংযোগ চালু করুন` দিয়ে পাওয়া কোড Android অ্যাপে দিন, অথবা `.rodshop` সংযোগ ফাইল খুলুন। চালু না করা পর্যন্ত LAN service listen করে না। শুধু পড়ার service port 3002; PC entry port 3000 এখনও loopback-only। বাইরে থেকে দেখতে PC-র Google Drive সংযোগ সেটআপ করে APK-তে RD1. কোড দিন।
- **অফলাইনে রিপোর্ট:** PC থেকে `মোবাইলের হিসাবের ফাইল নিন` দিয়ে JSON ফোনে নিয়ে খুলতে পারেন। Wi-Fi থেকে সফলভাবে পাওয়া বা import করা সর্বশেষ হিসাব অ্যাপের private storage-এ থাকে। PC বন্ধ থাকলে সেটিই পুরোনো বলে দেখাবে। App uninstall করলে ফোনের cache মুছে যাবে; PC-র ডেটা থাকবে।
- **রিপোর্ট:** পাশের `রিপোর্ট` মেনু খুলুন। দৈনিক/সাপ্তাহিক/মাসিক/বার্ষিক/নিজের তারিখ বেছে `রিপোর্ট দেখুন` চাপুন। সপ্তাহ শনিবার থেকে শুক্রবার; দুই প্রান্তের তারিখই অন্তর্ভুক্ত। আগস্টের ডামি ডেটা দেখতে `মাসিক` ও `আগস্ট ২০২৬` বেছে নিন।
- **রিপোর্টের বিস্তারিত:** `পণ্যভিত্তিক বিক্রি`তে পরিমাণ, একক, বিল সংখ্যা, গড় দর ও মোট বিক্রি; `ক্রেতাভিত্তিক বিক্রি`তে বিল সংখ্যা, বিক্রি, জমা, নতুন বাকি, আলাদা আদায় ও শেষের তারিখে পাওনা; `দিনভিত্তিক হিসাব`তে প্রতিদিনের বিক্রি, আদায় ও খরচ পাবেন। নাম দিয়ে খোঁজা ও বিক্রির অঙ্ক দিয়ে সাজানো যায়।
- **বাকির অর্থ:** নির্বাচিত বিলের বিক্রির সময়ের বাকি পরের আদায়ে কমিয়ে দেখানো হয় না। আলাদা বাকি আদায় পৃথক থাকে। শেষের তারিখে মোট পাওনা = সময়সীমার আগের পাওনা + এই সময়ের বিক্রির বাকি − এই সময়ের বাকি আদায়। এই মোটে আগের সময়ের হিসাব এবং এই সময় লেনদেন না করা ক্রেতার বকেয়াও থাকে। রিপোর্টের ক্রেতার টেবিলে এই সময় লেনদেন করা ক্রেতারাই আসে।
- **লাভ ও রপ্তানি:** লাভের রিপোর্টের আগে বিক্রি হওয়া মালের ক্রয়মূল্য নির্ধারণের পদ্ধতি যোগ করতে হবে। রিপোর্টের PDF/Excel export এই সংস্করণে নেই। রসিদ প্রিন্ট আগের মতো কাজ করে।
- **দোকানের সেটিংস:** নাম, ঠিকানা ও মোবাইল লিখুন; PNG/JPG/WebP লোগো বেছে `দোকানের তথ্য সেভ করুন` চাপুন। মূল ছবি সর্বোচ্চ ৫ MB; অ্যাপ সেটি সর্বোচ্চ ৫১২ পিক্সেলে ছোট করে রাখে। সেভ করা লোগো সর্বোচ্চ ৫০০ KB। লোগো সরানো যায়। তথ্য ও লোগো ডেটাবেসের ব্যাকআপেও থাকে। নতুন ও পুরোনো রসিদে সর্বশেষ সেভ করা দোকানের তথ্য দেখা যায়।
- **ক্রেতার ইতিহাস:** তালিকায় ক্রেতার নাম বা `ইতিহাস` চাপুন। প্রথম দিন থেকে সব বিক্রি ও বাকি আদায় পাওয়া যাবে; প্রতি পৃষ্ঠায় ২৫টি। রসিদ নম্বর, পণ্য, বিবরণ বা YYYY-MM-DD দিয়ে খুঁজুন; শুধু বিক্রি/আদায় ও পুরোনো/নতুন ক্রম বেছে নিতে পারেন। `দেখুন / প্রিন্ট` থেকে রসিদ খুলবে। বর্তমান পাওনা সব সময়ের হিসাব; সারিতে দেখানো বাকি হলো বিল সেভের সময়ের বাকি।
- **ক্রেতা খোঁজা:** নতুন এন্ট্রিতে ক্রেতার ঘরে নাম, ঠিকানা বা মোবাইল লিখে ফলাফল থেকে বেছে নিন। বাংলা অঙ্কের মোবাইল দিয়েও খোঁজা যায়। Arrow ও Enter ব্যবহার করা যায়।
- **এন্ট্রির ক্রম:** বিক্রি → বাকি আদায় → মাল কেনা → দেনা পরিশোধ → খরচ।
- **প্রিন্ট:** এন্ট্রি সেভের বার্তার `রসিদ দেখুন / প্রিন্ট` খুলে `রসিদ প্রিন্ট করুন` চাপুন। Chrome-এর print dialog-এ প্রিন্টার বা Save as PDF বেছে নিন। রসিদের বিন্যাস A4 portrait। সাম্প্রতিক লেনদেনের `প্রিন্ট` থেকেও পুরোনো রসিদ খুলবে। বাস্তব প্রিন্টারে কাগজে ছাপানো এখানে পরীক্ষা করা হয়নি।
- **ক্রেতা:** তালিকায় নাম/ঠিকানা/মোবাইল দিয়ে খুঁজুন। `সম্পাদনা` দিয়ে তথ্য বদলান। বাকি শূন্য হলে `মুছুন` দিয়ে তালিকা থেকে সরাতে পারবেন; আগের হিসাব ও রসিদ থাকবে। `মুছে রাখা তালিকা` থেকে ফেরত আনা যায়। নাম বদলালেও পাওনা একই ক্রেতার সঙ্গে যুক্ত থাকে। পুরোনো রসিদে সেভের সময়কার নাম/ঠিকানা/মোবাইল থাকে।
- **একাধিক পণ্য:** বিক্রি ও মাল কেনার ফর্মে `আরও পণ্য যোগ করুন` চাপুন। সর্বোচ্চ ৫০টি সারি দেওয়া যায়। পুরো বিলের জন্য জমা একবার দিন; মোট, বাকি ও সব পণ্যের স্টক একসঙ্গে সেভ হয়।
- **একক:** পণ্য যোগ করার সময় `কেজি (KG)` বা `পিস (Pcs)` বেছে নিন। কেজিতে তিন ঘর দশমিক চলে; পিসে পূর্ণ সংখ্যা লাগে। সিমেন্টের প্রতিটি বস্তা এক পিস ধরে রাখতে পারেন। পুরোনো পণ্যের একক কেজি রাখা হয়েছে।

পুরোনো ডেটাবেস প্রথমবার খুললে schema ২-এ উন্নীত হয়। পুরোনো ক্রেতার নামগুলো স্বয়ংক্রিয়ভাবে তালিকায় আসে; তাদের ঠিকানা ও মোবাইল পরে সম্পাদনা করে যোগ করুন। upgrade-এর আগের backup `data/backups/before-v2-...sqlite` নামে রাখা হয়েছে।

## ৬. স্বয়ংক্রিয় কাজ কীভাবে চলছে

`npm run dev` তিনটি process চালায়: PC app, owner preview এবং background worker। Worker browser tab-এর ওপর নির্ভর করে না।

- প্রতি ৩০ মিনিটে **লোকাল** owner snapshot।
- প্রতি ৬০ মিনিটে যাচাই করা **লোকাল** SQLite backup।
- অ্যাপ আবার চালালে সময় পার হয়ে যাওয়া কাজ পরের tick-এ হবে।
- অ্যাপ/Terminal বন্ধ থাকলে বা PC sleep করলে worker চলবে না। সবসময় চালুর service পরের ধাপে।
- Google Drive সংযোগের পরে worker পরিবর্তন আছে কি না প্রতি ৩০ সেকেন্ডে দেখে; পরিবর্তিত রিপোর্ট আপলোড করে এবং অন্তত প্রতি ৩০ মিনিটে refresh করে। যাচাই করা database backup প্রতি ৬০ মিনিটে আপলোড হয়। সংযোগ না দিলে backup ও snapshot শুধু লোকাল থাকে। পুরোনো snapshot হলে mobile preview-তে সতর্ক অবস্থা দেখাবে।
- Owner preview খোলা থাকলে ৩০ সেকেন্ড পরপর নতুন snapshot আছে কি না দেখে। App বন্ধ থাকলে আবার খুললে সর্বশেষ তথ্য পড়বে।

হাতে snapshot/backup:

```bash
npm run snapshot
npm run backup
```

## ৭. কী পরীক্ষা করা হয়েছে

```bash
npm test
npm run build
```

স্বয়ংক্রিয় test-গুলো আলাদা অস্থায়ী database ব্যবহার করে; নিজের দোকানের data বদলায় না। বিক্রি/স্টক/বাকি, duplicate request, multi-item rollback, কেজি/পিস, ক্রেতার নাম বদল/মুছে রাখা/ফেরত আনা, receipt contact snapshot, পুরোনো schema থেকে migration, Dhaka দিনের সীমা, লোগোসহ backup থেকে restore এবং ২০টির বেশি রসিদের ইতিহাসে pagination/filter/sort পরীক্ষা করে। রিপোর্টে মিশ্র পণ্যের বিল একবার গণনা, পণ্য/ক্রেতার সঙ্গে মোটের মিল, মাস/সপ্তাহ/লিপ ইয়ারের সীমা, আগের ও শেষের পাওনা এবং আদায়/কেনা/খরচ আলাদা থাকার পরীক্ষাও আছে। মোবাইল snapshot রিপোর্ট PC-র SQL রিপোর্টের সঙ্গে মিলিয়ে, token ছাড়া প্রবেশ বন্ধ এবং মোবাইল থেকে লেখা বন্ধ থাকার পরীক্ষাও আছে। Production build তৈরি হলে `npm start` দিয়ে এই কম্পিউটারে চালানো যায়।

## ৮. বর্তমান সীমা

- PC entry app কেবল loopback-এ চলে। আলাদা read-only LAN service চাইলে চালু করা যায়। এই ধাপে PC login নেই।
- Android APK-তে bundled dashboard ও Drive থেকে বাইরে থেকে হিসাব পড়ার কোড আছে। নিজের Cloud project-এর Desktop/Android client এবং consent ছাড়া Drive সংযোগ চলবে না।
- বিক্রি, মাল কেনা, বাকি আদায়, দেনা পরিশোধ ও খরচ আছে। এক বিলে কেজি ও পিসের পণ্য মেশানো যায়।
- পুরোনো পাওনা-দেনা যোগ করা, ফেরত, ভুল entry সংশোধন, discount, transport allocation ও profit report পরের ধাপে।
- **দোকানের সেটিংস** থেকে দোকানের নাম, ঠিকানা, মোবাইল ও লোগো বদলানো যায়।
- Backup মুছবেন/restore করবেন না, যতক্ষণ app চলছে। Restore UI, encryption, key recovery ও retention পরের ধাপে।
- Repository-তে Google credential, দোকানের database, ব্যক্তিগত screenshot, signing key বা প্রস্তুত APK রাখা হয় না। নতুন clone-এ নিজের সংযোগ আলাদাভাবে সেটআপ করতে হবে।

## ৯. পরের কাজ

1. Local app-এর প্রয়োজনীয় হিসাব ও login সম্পূর্ণ করা।
2. একটি Google Cloud project-এ Drive API/OAuth setup; credential নিজে local configuration-এ দেবেন, chat-এ নয়।
3. PC upload যাচাই করা হয়েছে; বাস্তব Android ফোনে authorization/download যাচাই।
4. Android-এ offline cache এবং ৩০ মিনিটের remote update পরীক্ষা; dashboard-এর static hosting প্রয়োজন নেই, APK-তে bundled আছে।
5. Windows background service, startup, backup encryption/retention এবং নতুন PC-তে recovery পরীক্ষা।

Android APK build, signing key সংরক্ষণ ও install-এর বিস্তারিত `android/README.md`-এ। পূর্ণ Google Cloud নির্দেশনা `android/GOOGLE-DRIVE-SETUP.txt`-এ।
